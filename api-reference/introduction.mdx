This reference covers the REST endpoints an **integrator** uses. Most of your real-time work —
sending messages, typing, presence, receipts, call signaling — happens over the
[WebSocket](/websocket/overview) (usually via the [SDK](/sdk/overview)). REST is for
**provisioning tokens, reading history, and fetching config**.

<Warning>
  **Messages are sent over the WebSocket, not REST.** Use
  `client.conversations.get(id).sendMessage(...)`. REST endpoints are for history and setup.
</Warning>

## Base URL

```
https://dev.vocantly.com/api/v1
```

All endpoints are under the `/api/v1` prefix. Use your production host in production.

## Authentication

Depending on the endpoint, you authenticate with one of:

| Method | Header(s) | Used by |
|--------|-----------|---------|
| **API key** | `X-Api-Key: pk_…` + `X-Api-Secret: sk_…` | Server-to-server (provisioning) |
| **Public key** | `X-Api-Key: pk_…` (+ allow-listed `Origin`) | Anonymous browser sessions |
| **SDK token** | `Authorization: Bearer <sdk_token>` | The visitor's frontend |

See [Authentication & tokens](/guides/authentication) for the full picture. Keys stay on your
backend; the browser only ever gets a token.

## Response format

Every response is wrapped in a consistent envelope:

```json
{
  "success": true,
  "message": "…",
  "data": { }
}
```

Errors use the same shape with `success: false` and an HTTP status code:

```json
{
  "success": false,
  "message": "Invalid API credentials",
  "statusCode": 401
}
```

| Status | Meaning |
|--------|---------|
| `400` | Validation error |
| `401` | Missing/invalid credentials |
| `403` | Not allowed (disabled app, origin not allow-listed, wrong role) |
| `404` | Resource not found |
| `429` | Rate limited |
