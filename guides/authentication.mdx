Everything a visitor's browser does — connecting the SDK, joining conversations, sending
messages — is authorized by a short-lived **SDK token**. This page explains the credentials
involved and the three ways to obtain a token.

<Warning>
  **Keys stay on your backend. Tokens go to the browser.** Your App ID, public key (`pk_…`),
  and especially your secret key (`sk_…`) must never appear in frontend code. The frontend only
  ever receives a **token**.
</Warning>

## Credentials

| Credential | Where it lives | What it's for |
|-----------|----------------|---------------|
| **App ID** | Backend | Identifies your app (UUID) |
| **Public key** `pk_…` | Backend / allow-listed sites | Server auth, and anonymous browser sessions |
| **Secret key** `sk_…` | **Backend only** | Server-to-server auth; never expose it |
| **SDK token** | Frontend | Short-lived JWT the SDK/widget connects with |
| **Dashboard JWT** | Your admin app | Owner/admin/agent access to management APIs |

Create an app in the dashboard to get its App ID, public key, and secret key. You can rotate
the secret at any time (`POST /apps/:id/rotate-secret`) — it's shown only once.

### 1. Mint a token (server-to-server)

Your backend calls `POST /api/v1/apps/:appId/tokens` with either your API keys or a dashboard
JWT, and returns the token to your frontend.

```bash
curl -X POST https://dev.vocantly.com/api/v1/apps/YOUR_APP_ID/tokens \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: pk_xxxxx" \
  -H "X-Api-Secret: sk_xxxxx" \
  -d '{ "external_user_id": "user_123", "name": "Jane", "email": "jane@example.com" }'
# → { "data": { "token": "…", "expires_in": 86400, "user_id": "user_123" } }
```

Use this when you already have conversations (e.g. an [external conversation](/api-reference/conversations/create-external)
for an order or appointment chat) and just need to authorize the current user. Full reference:
[Issue SDK Token](/api-reference/apps/issue-token).

### 2. Start a support session (one call)

For a support widget, `POST /api/v1/apps/:appId/support-sessions` mints the token **and**
creates the support conversation together, returning both `token` and `conversation_id`. See
[Start a Support Session](/api-reference/support-sessions).

### 3. Anonymous session (no backend)

A static site can provision entirely in the browser using only the **public key**:
`POST /api/v1/sdk/anonymous-session` with `X-Api-Key: pk_…`. The request's `Origin` must be in
the app's **allowed origins** (secure by default — empty means disabled). See
[Open an Anonymous Session](/api-reference/anonymous-session).

## Using a token

Once your frontend has a token, hand it to the SDK or widget — it manages the WebSocket
connection and auth for you:

```typescript
import { Vocantly } from '@vocantly/sdk';

const client = new Vocantly({ wsUrl: 'wss://ws.dev.vocantly.com/ws', token });
await client.connect();
```

Connecting to the WebSocket directly instead? See [WebSocket Authentication](/websocket/authentication).

## Token lifetime & refresh

SDK tokens are short-lived. When you issue a fresh token (e.g. on page load), update the client
without tearing down your app state:

```typescript
client.updateToken(newToken); // then reconnect if needed
```

## Dashboard authentication

Your **own admin app** (not the visitor-facing frontend) authenticates dashboard users with a
JWT via `POST /api/v1/auth/login`, and refreshes it via `POST /api/v1/auth/refresh`. These
tokens carry a `role` (OWNER, ADMIN, AGENT, MEMBER) and are used for management APIs like bot
config, FAQs, the support inbox, and agent tools.

## Security checklist

<CardGroup cols={2}>
  <Card title="Secret stays server-side" icon="lock">
    Never ship `sk_…` (or App ID / public key for server auth) to the browser.
  </Card>
  <Card title="Allow-list origins" icon="shield">
    For anonymous embeds, add only the exact sites you trust to the app's allowed origins.
  </Card>
  <Card title="HTTPS / WSS only" icon="wifi">
    Always use TLS in production for both the API and the WebSocket.
  </Card>
  <Card title="Rotate secrets" icon="rotate">
    Rotate the app secret if it may have leaked (`POST /apps/:id/rotate-secret`).
  </Card>
</CardGroup>
